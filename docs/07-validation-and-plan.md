# 07 受け入れ条件

現行仕様の受け入れ条件を記載する。実行済みの結果を表すものではない。公開前の作業は[リリース手順](release.md)を参照。

## 受け入れ条件

| ID | 要件 | 確認方法・期待結果 |
|---|---|---|
| AC01 | UI-01/02 | 起動時はソース一覧。タブは「ソース一覧」「設定」の2つ。空状態から追加できる |
| AC02 | SRC-01/02 | 名前・URLのみ入力して追加できる。形式・言語・文字コードは自動、間隔は24時間 |
| AC03 | SRC-03 | 正常ファイルの取得・解析・保存後だけ一覧へ追加され、単語を開ける |
| AC04 | SRC-03 | オフライン・HTTPエラー・解析失敗・保存失敗で登録されず、直前の追加画面に全入力が残る。修正・再試行で追加できる |
| AC05 | SRC-02/08 | 全オプションを後から変更できる。取得設定の変更に失敗しても旧設定・旧単語は残り、編集入力も失わない |
| AC06 | SRC-04/05 | 一覧に名前・最終更新・間隔・件数・トグルがある。1時間未満は「1時間以内」、3時間台は3時間前、24時間ちょうどは24時間前、24時間超は日時 |
| AC07 | SRC-04/05 | 件数は検索前の単語一覧総数と一致。更新失敗時は件数と時刻が不変。正常304では取得確認時刻が更新される |
| AC08 | SRC-06 | トグルで有効／無効を変更。無効時は定期実行を止め、保存済み単語を閲覧可能。再有効化で保存した間隔を使う |
| AC09 | SRC-07 | 複数選択、全選択、解除、一括有効化・無効化・削除を実行できる。選択中タップで詳細へ遷移せず、トグル操作と競合しない |
| AC10 | SRC-07 | 削除確認は対象数を示して1回。受け付けられなかったソースだけ選択に残る。ユーザー辞書への書き込みの失敗は各ソースに表示され、再試行できる |
| AC11 | VIEW-01/02 | 通常のソースタップで単語一覧。単語編集・削除・追加・個別除外がなく、検索とオフライン閲覧が可能 |
| AC12 | SYNC-01 | ソースごとに異なる間隔を保存でき、Workerの周期と対象が一致。対応端末では取得後に毎回の承認なしで反映する |
| AC13 | SYNC-02/03 | 同一内容の再同期で重複しない。片方の取得失敗は旧データを保持し、他ソースの更新を妨げない |
| AC14 | SRC-06/SYNC-03 | A/B共有語はAの無効化・削除後も残る。最後の参照が外れた未変更の管理行のみ削除。手動語・外部編集語は保護 |
| AC15 | 最小限の検証 | 名前・URLの空欄は防ぐ。クエリを変えない。任意設定の操作を強制せず、正常な0件や大量の内容変更に独自の承認閾値を設けない |
| AC16 | 表示・操作維持 | 回転で入力・検索・複数選択が残る。大きな文字とTalkBackでトグル・選択状態を識別できる |
| AC17 | UI-01/SYNC-01 | 初回起動でセットアップを表示し、未完了のままでも「はじめる」でソース一覧へ進める。以後の起動はソース一覧。設定のバックグラウンド実行で電池の最適化の状態を表示し、除外の確認画面を開ける |

## 検証の範囲

まず合成辞書と偽Providerで追加成功／失敗、状態切替、一括処理、参照共有を確認する。UIでは2タブ・フォーム復帰・一覧表示・閲覧専用を確認する。未公開の間はschemaの移行処理を持たない。公開後のschema変更では既存データを保持する移行試験を行う。

既存の解析・HTTP・所有権保護の試験は維持する。変更した経路に必要な試験を追加し、要件と無関係な極端な入力、まれなID再利用、全停止点の総当たり、全OEMの省電力状態を新しい完了条件にしない。

実Providerへの書き込みを伴う確認は、検証用パッケージ（`-PisolatedAcceptance=true`）と人工語で小規模に行う。過去の端末での通過を、変更後の合格判定に流用しない。
