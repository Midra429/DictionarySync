# 02 対応形式と変換

現行パーサーの対応範囲を記載する。出典は[08](08-references.md)を参照。

## 対応形式と文字コード

| パーサーID | 入力構造 | 文字コード・改行 | 対応 |
|---|---|---|---|
| `ime-tsv-v1` | 読み TAB 単語 TAB 品詞 [TAB コメント]、3または4列 | hyakkano・GitHubルート=UTF-8 BOMなし/LF、ATOK版=UTF-16LE BOMあり/LF、MS-IME版=UTF-16LE BOMあり/CRLF | 対応。名称でMozc/ATOK/MS-IMEを別形式にしない |
| `ms-wordlist-v1` | `!Microsoft IME Dictionary Tool`、`!Format:WORDLIST`等のヘッダー、続いて同じ3/4列TSV | hyakkanoは**UTF-16LE BOMなし**、HTTP charset=utf-16le、CRLF | 対応。BOMなしでも既知ヘッダーのバイト並びを根拠に判定。Mozcの取り込みと同様に5列目以降も受理し、空でない値はコメントに連結する（コメント前のタブの重複など）。ヘッダーのないTSVは3〜4列のまま |
| `atok-tango-v1` | `!!ATOK_TANGO_TEXT_HEADER`（大小文字不問）または`!!DICUT11`以降、続いて読み TAB 単語 TAB 品詞 [TAB 単語コメント TAB 自動置換 TAB 置換候補1〜5] | UTF-8/UTF-16（BOMなしは既知ヘッダーで判定）、Windows-31Jは手動 | 対応。`!!`で始まる行は位置・内容を問わず注釈行。第4列はコメント。自動置換は空欄・`しない`のみ受理し、`する`や置換候補があればソース全体を不採用（UserDictionaryに対応する機能がなく、コメント扱いもしない）。`!!DICUT10`以前は未対応 |
| `gboard-v1` / `gboard-v2` | `# Gboard Dictionary version:1`＋ショートカット TAB 単語 TAB 言語タグの3列／`version:2`＋`# Gboard Dictionary format:shortcut\tword\tlanguage_tag\tpos_tag`（`\t`はタブ）＋4列 | UTF-8 | 対応。第3列は品詞ではなく言語タグ（空欄=すべての言語）。v2はformat行が必須で、既知の列順以外は未対応。format行（タブを含む）を単語にしない。ZIP配布はそのままでは取得できない |
| `apple-plist-xml-v1` | plist(version=1.0) > array > dict、string型の`phrase`と`shortcut` | 両配布元ともUTF-8 BOMなし、XML宣言、LF | 対応。一般のApple辞書DBではなくこのテキスト置換構造のみ |
| `apple-csv-v1`（形式指定`APPLE_CSV`） | Apple日本語入力の追加辞書：読み,単語,品詞 または 読み,単語,品詞,,メモ | GitHub macos-compatibleはUTF-8 BOMなし/LF | 3列と、カンマ2つの後にメモを置く5列の両方に対応（行ごとに混在可）。手書きの`読み,単語,品詞,メモ`（4列）も第4列をメモとして受理。引用符を扱うCSV解析。5列で非空の第4列は不正。Apple側の文字数上限（読み32・単語64・1行127）は取り込み先の制約なので適用しない |

### 列数の許容範囲

- 各形式の最大列数を超える末尾の空列（行末の余分なタブ）は無視する。空でない値がある場合は列数エラー（MS-IMEを除く）。
- 形式が確定している場合（ヘッダーのある形式、または形式を手動指定した場合）、3列に満たない行と、タブだけの行はMozcと同様に読み飛ばす。読み飛ばした行数と最初の行番号を取得版に記録し、単語一覧の先頭に表示する。すべての行を読み飛ばした場合は形式の誤りとしてエラーにする。
- ヘッダーのないTSVを自動判定する場合と、ヘッダーのないCSVを自動で候補にする場合は、列数が辞書であることの唯一の根拠なので読み飛ばさない。

ヘッダーのある形式はヘッダーで列の意味を決め、拡張子や形式名から推測しない。手動の「IME共通TSV」を選んでも、ATOK・Gboardのヘッダーがあればその形式として解析する。

### 対応しない形式

次は認識したうえで形式名を示すエラーにし、列数エラーや単語として読み進めない。

| 形式 | 判定 | エラー |
|---|---|---|
| SKK（`SKK-JISYO.*`） | 行頭`;; okuri-ari entries.`／`;; okuri-nasi entries.`。ASCIIなので復号前（EUC-JPのまま）に判定 | `SKK_UNSUPPORTED` |
| Rime（`.dict.yaml`） | `#`コメントの後の最初の行が`---`で、`...`行がある。`code`列は日本語の読みではない | `RIME_UNSUPPORTED` |
| JISYO構造化辞書のYAML等 | 先頭が`---`のYAML文書。JSONは従来どおりHTML/JSON判定で拒否。MessagePackはテキストとして復号できず失敗する | `YAML_UNSUPPORTED` |
| 圧縮・アーカイブ | ZIP・gzip・xz・bzip2・7z・zstd・tarのマジック。展開はしない | `UNSUPPORTED_BINARY` |
| ATOK旧形式・Gboardの未知バージョン | `!!DICUT10`以前、`version:`が1/2以外、未知のformat行 | `ATOK_DICUT_UNSUPPORTED`、`GBOARD_VERSION_UNSUPPORTED`、`GBOARD_FORMAT_UNSUPPORTED` |

文字コードの初期サポートはUTF-8、UTF-16LE/BE（BOM対応）、手動指定のWindows-31J。UTF-16BE・Windows-31Jは合成データで検証。Shift_JISという曖昧な表示だけにせずWindows-31J（CP932）と明記する。EUC-JP等は初期対象外（SKKは上記のとおり形式として不採用）。ATOK対応はテキスト単語ファイルのみで、ネイティブ辞書全般の対応とは呼ばない。

### 自動判定の順序

1. ステータス・取得完了・バイト数・圧縮・先頭内容を確認。HTML MIME、HTMLのDOCTYPE/html要素、JSONエラー、圧縮・アーカイブ/bplistのマジック、SKKの見出しを識別し、対象外なら同期しない。汎用octet-stream/text/plainだけでは失敗にしない。
2. BOMを優先する。UTF-32等の非対応BOMはUTF-16と誤認しない。BOMとHTTP charset/XML宣言が矛盾すればエラーにする。
3. BOMなしの既知ヘッダー（MS-IME・ATOK・`!!DICUT`・Gboard・XML宣言）をUTF-16LE/BEのバイト配列として検出する。HTTP charsetは補助根拠。一般ファイルをNULの割合だけでUTF-16と決めない。
4. 残りは厳密UTF-8を試す。復号の置換文字で読み進めない。不成立なら手動文字コードを案内。Windows-31Jの自動推測はしない。
5. YAML文書（Rime等）を除外する。XMLならルートと型を検査。TSVは最初の非空行のヘッダーでMS-IME・ATOK・Gboard・ヘッダーなしを決め、それぞれの列数を全データ行で検査する。ヘッダーのないTSVはMozcかMS-IMEかのブランドを無理に断定せず「IME共通TSV」と表示する。ヘッダーのないCSVは他用途の表と区別する根拠が弱いため、自動では全体を検証したうえで候補提示にとどめ、初回に`apple-csv-v1`を手動指定して確認する。
6. 自動で判定できない場合や未対応の構造は、形式指定または配布ファイルの確認を案内する。手動指定も破損チェックは回避しない。「自動」の設定は保持し、取得ごとの解決結果を記録する。以前と異なる対応形式だったことだけを理由に承認を要求しない。

全体の検証を終えてから反映計画へ進む。サンプル先頭だけ正常でも採用しない。

## 項目対応と入力規則

| 入力 | アプリ内 | UserDictionary |
|---|---|---|
| 読み／plist shortcut／Gboardショートカット | 原文を保持。空のshortcutはNULL相当に正規化 | `SHORTCUT`。日本語以外の略語もそのまま |
| 単語／plist phrase | 原文を保持。空文字は禁止 | `WORD` |
| 品詞／Gboard v2 pos_tag | ソース・行ごとの文字列として保持。未知の品詞も文字列として受理。IMEごとに体系が違うため変換・同一視しない（ATOKの`$`・`*`記号も原文のまま）。Gboard v1は空 | 列なし。捨てたのではなく未反映情報として表示 |
| コメント／CSVメモ／ATOK単語コメント | ソースごとに全バリエーションを保持 | 列なし |
| CSV第4列 | 5列の行で空欄のみ受理。意味を推測しない | なし |
| ATOK自動置換・置換候補 | 空欄と`しない`のみ受理。それ以外はソース全体を不採用 | なし |
| 言語 | ソースの明示指定、または自動の解決値（01）。自動ではGboardの言語タグを単語ごとに使い（空欄は「すべての言語」）、複数言語が混在してもそのまま扱う。言語タグのない形式・単語は`ja`。明示指定はファイルの言語タグより優先し、全単語をその言語にする。解決した言語は単語ごとに保存するProviderへ渡す値はBCP 47に正規化 | LocaleからProvider互換表記へ変換（基本は`Locale.toString()`）、全言語はNULL |
| 出現重複 | 行数とメタデータを保持、同一キーは1件 | 重複によってfrequencyを増やさない |
| frequency | 初期値128 | 128。配布元の品詞・並び順から推測しない |

- 空行は無視。TSVではタブを含まない行頭`#`をコメント、MSヘッダー付き形式ではタブを含まない行頭`!`、ATOK形式では行頭`!!`の行（公式仕様の注釈行）、Gboard v2ではformat行をヘッダー／コメントとして扱う。読みが`!`や`#`で始まるデータ行を誤って除外しない。ヘッダー不明・不正行は行番号・理由を表示し**ソース全体を不採用**とする。行を黙ってスキップするモードは作らない。
- CRLF/LF/CRを行区切りとして処理し、最終行の改行欠如は単独では破損にしない。引用内改行など、このプロファイルで扱わない制御文字を含む値は不正とする。
- 前後スペース、全角半角、かな種、大小文字を登録データでは勝手に変えない。NFC/NFKCでword/shortcutを統合しない。合成文字、異体字セレクタ、ZWJ絵文字も保持する。不正サロゲート、NUL、埋め込みタブ・改行等の制御文字を拒否する。空白だけの単語もエラー。
- 検索専用にNFKC・小文字化等の補助キーを作ってよいが、表示・同一性キー・Providerへの値とは分離する。
- ファイル全体の容量上限を資源保護の基本とし、フィールドごとの細かい文字数上限は現行要件の必須条件にしない。容量上限は[README](../README.md)を参照。文字の切り捨てやIME対応長の推測は行わない。
- XMLはストリーム解析。標準Apple DOCTYPE宣言は受理しても**外部DTDを取得しない**。内部サブセット・外部エンティティを拒否し、対応するテキスト置換構造を解析する。重複キーや単語を解釈できない構造は不正とする。細かな深さ・キー数の独自上限を追加することは要件にしない。`&amp;`等の標準エスケープは復号する。XMLの`<array/>`は構造上有効な空辞書として0件を受け入れる（05）。
- plistのコメント・品詞は存在しないため復元しない。メタデータだけの変更はアプリ内に反映し、Provider行を書き換えない。

## 配布データの扱い

外部の辞書本文は同梱せず、ユーザーが指定した直接HTTPS URLから取得する。テストは合成辞書を基本とする。配布元の利用条件はそれぞれ確認する。出典は[08](08-references.md)を参照。
