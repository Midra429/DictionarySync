# 05 データと同期

以下は現行要件に必要な論理モデル。実装はRoom schema 1（`app/schemas`）。参照の世代番号 `reference_generation` を含む。削除済み履歴のURLを再利用できるようURL索引は一意にせず、現行ソース間の重複はSyncCoordinator内で確認する。

## データ

| データ | 必要な項目・役割 |
|---|---|
| Source | ID、名前、URL、形式指定、言語指定、文字コード指定、`enabled`、`syncInterval`（初期24時間）、設定revision、最新の正常取得版ID、最終取得成功時刻、同期状態・エラー |
| Snapshot | ソースID、設定revision、解決済み形式・言語・文字コード、取得日時、項目数、本文／内容ハッシュ、既存のHTTP validator |
| Entry | Snapshot ID、単語、読み、品詞・コメント、解決済み言語。原文の項目を保持し、言語は単語ごとに解決した値 |
| SourceReference | ソースと共有辞書のキーの対応。有効ソースが必要とする内容を管理 |
| ProviderBinding | アプリが挿入した行IDと書込後の値、既存一致の区別 |
| 既存の要求・操作記録 | 未処理要求と未完了のProvider操作を再開するために使用。独立した履歴／競合テーブルは持たない |

一覧の件数は最新正常SnapshotのEntry数（重複行を含む）。共有辞書の管理行数とは別。日時はUTCで保存し、表示時に端末タイムゾーンへ変換する。

言語は設定値`AUTO`と解決値を区別する。自動ではファイルが単語ごとに宣言した言語（Gboard）を使い、宣言がなければ`ja`へ解決する（01）。手動指定は全単語に適用する。Snapshotの解決済み言語は宣言のない単語に使う既定値で、反映キーにはEntryの言語を使う。URL・形式・言語・文字コードの変更で設定revisionを更新し、古い条件の取得結果を新設定へ混ぜない。

## 初回追加と編集

1. 未保存フォームの名前・URLとオプションを受け取る。
2. 取得・復号・解析を行う。正常な空辞書は0件として成功できる。HTML・構文不正・通信失敗は成功にしない。
3. 成功したSourceとSnapshot・Entryを同じRoomトランザクションで保存する。保存失敗時は全体をロールバックする。
4. 保存が完了したら一覧に表示し、定期実行を登録する。有効ソースの共有辞書反映は別の成功状態として管理する。

失敗時はフォーム入力を保持する。登録済みソース、定期要求、Provider行を残さない。取得成功後にProvider反映が失敗した場合はソースを取り消さず、同期失敗として再試行できるようにする。

既存ソースの取得設定を編集するときは、候補設定で取得が成功するまで旧設定・旧単語を保持する。名前と間隔だけの編集は再取得不要。無効なソースを編集して取得が成功しても、自動的に有効へ戻さない。

## ソースの有効／無効・削除

`enabled`はソースを同期に使うかを表し、定期同期もこれだけで決まる（定期取得だけを止める別の設定はない）。

| 操作 | 設定・取得済み単語 | 定期同期 | 共有辞書 |
|---|---|---|---|
| 追加成功 | 保存 | 初期24時間で登録 | 有効ソースとして反映 |
| 無効化 | 保持 | 停止 | そのソースの参照を外し、他に参照のない未変更の管理行と完全一致の既存行を削除 |
| 再有効化 | 保持 | 保存した間隔で再開 | 保存済み正常版から反映。取得期限超過なら再取得 |
| 削除 | 一覧から除外し、履歴用データを保持 | 停止 | 無効化と同じ参照解放。所有権・復旧用の記録は保持 |

有効化・無効化・削除・追加後の反映は、希望状態を保存した後、バックグラウンドの反映処理（06）が行う。ユーザー辞書に何も反映していないソースの無効化・削除はその場で完了する。共有辞書処理に失敗したら、希望状態と「反映できませんでした」を区別して表示し、「反映を再試行」で再び順番待ちにできる。トグルをOFFにできても、すべての語を除去済みとは表示しない。切替後の古い定期要求は処理開始前に対象外と判定する。

一括操作は選択sourceIdを順に同じ個別処理へ渡す。他ソースを巻き戻さず、成功／失敗をそれぞれ返す。削除の確認は一括操作の前に1回だけ行う。

## 共有辞書への反映で維持する基本規則

反映キーは`K = (Entryの解決済み言語, 単語, 読み)`。同じ単語・読みでも言語が違えば別キー。同じ読みの異なる単語は別キー。同じ語を複数の有効ソースが参照するときは共有する。品詞・コメントは閲覧情報として保持し、Providerへ無理に変換しない。

- 同じキーの既存行があれば再利用するが、アプリ所有とは扱わず、値を上書きしない。ソースの無効化・削除では、ほかの管理行と同じく削除する。
- 一致行がなければ追加し、返却IDと読戻し結果を既存の操作記録に残す。照会・記録は最大900語のまとまりごとに行う（04「性能と保存」）。
- 削除できるのは、他の有効ソースから参照されない行のうち、アプリが追加したと確認でき値が最後の記録と一致する行と、無効化・削除するソースのキーに完全一致する既存行（重複を含む）だけ。アプリが追加した後に外部編集された行と、診断の確認用の行は残す。ソースの更新で外れたキーの既存行は削除しない。
- 取得・解析失敗時は前回の正常版と参照を維持する。正常な空辞書や通常の配布内容変更は差分として扱い、削除率20%・1,000件などの独自承認閾値は設けない。
- Provider書込は既存Coordinatorで直列化する。未完了操作は記録と実際の状態を照合して再開し、同じ追加・削除を無条件に再発行しない。
- 読み取り不能・外部編集等を検出した場合は対象の反映を止め、理由を表示する。閲覧は継続できる。

Roomと共有Providerをまたぐ完全な原子性はない。途中失敗を成功と表示せず、既存の再開処理を使う。まれなID再利用・外部同時書込を完全に解決する新機構や、自動補償の拡張は対象外とする。
