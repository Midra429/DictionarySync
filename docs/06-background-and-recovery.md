# 06 自動同期と失敗時の扱い

ソースの有効／無効は[05](05-data-and-sync.md)、画面上の表示は[03](03-ui.md)に定義する。

## スケジュール

- 間隔はソース単位で保存し、初期値は24時間。初回取得は追加操作の中で行い、最初の定期実行はその後の指定間隔を目安とする。
- 有効ソースごとに一意な定期Workを登録する設計とする。間隔変更時は置き換え／更新し、無効化・削除時は取り消す。
- WorkManagerは起動役とし、実際の処理は既存のRepositoryとCoordinatorを使う。開始前にソースの有効状態と設定を確認する。共有辞書の書込は直列に行う。
- 通常の周期は「取得・解析・保存→差分反映」。失敗時の旧データ保持は05に従う。WorkerはSyncEngineで通常の差分を自動反映する。
- OS・通信条件により遅延するため、指定時刻どおりの実行は保証しない。正確なアラームや常駐サービスは追加しない。

## 通信条件

既存のWi-Fiのみ設定は全体設定として維持し、初回追加・手動・定期のすべてへ適用する。Wi-Fiと非従量制は同義にしない。条件を確認できない場合は理由を表示して待ち、別回線へ勝手に切り替えない。VPN利用中はWi-Fiとみなさず待機する。

初回追加では条件待ちも登録成功とせず、入力を保持した追加画面に戻す。登録済みソースの定期処理では既存の待機・再試行を使う。省電力設定の変更やバッテリー診断を、追加・閲覧の前提にしない。

## 電池の最適化

Doze・App Standbyでは周期Workがメンテナンス枠と待機バケットの割り当てまで遅れる。初回セットアップと設定の「バックグラウンド実行」で除外の状態を表示し、`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（除外済みなら一覧）を開けるようにする（`BackgroundAccess`）。開けない場合はアプリ情報、それも開けない場合は案内を表示する。除外は任意で、追加・閲覧・手動同期の前提にしない。

対象はminSdk以上のどの端末にもあるこの設定だけとする。バックグラウンドの制限（Android 9以上）、未使用時の一時停止（Android 12以上）、データセーバー、OEM独自の省電力（Samsungのスリープ中のアプリ等）は、端末やOSの版によって有無や名称が異なるため扱わない。直接要求に使う`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`はGoogle Playで用途が制限されるため、配布先が決まったら[リリース手順](release.md)の注意を確認する。

## 失敗時の扱い

| 条件 | 処理 |
|---|---|
| 初回取得・解析・保存の失敗 | ソースを登録せず、直前の入力フォームで理由と再試行を表示 |
| 登録済みソースの取得・解析失敗 | 前回の設定・単語・件数・最終更新を保持。該当ソースにエラー表示 |
| 一時的な通信失敗 | 登録済みソースは既存の上限付き再試行を使用。初回追加で長い自動再試行待ちを強制しない |
| 形式不一致・不正ファイル | 設定または配布内容の修正後に再試行。空辞書扱いにしない |
| 正常な空辞書 | 0件として保存し、通常の差分反映。独自の大量削除承認フローを要求しない |
| Provider非対応・読み取り不能 | 共有辞書への反映を止め、未反映と理由を表示。ソース追加・閲覧は利用可能 |
| Provider操作の中断・外部変更 | 既存の操作記録に基づいて再開または停止。完了を確認できない状態を成功にしない |
| 一括処理の一部失敗 | 受け付けた希望状態は保持し、受け付けられなかったソースだけ選択に残す。書き込みの失敗は各ソースに表示し、「反映を再試行」で再開する |

HTTPは上限付き再試行とRetry-After待機を利用する。初回追加がRetry-Afterを受けた場合も理由をフォームに表示し、フォーム状態に待機期限を保持して早すぎる再試行を抑止する。そのためにソースを仮登録しない。

## 再開と復旧の範囲

初回取得の途中でキャンセルされた場合は未保存候補を破棄する。フォームの「取得を中止」（取得中の閉じる・戻る操作も同じ）で、止まった通信も含めて中止でき、何も登録されず入力は残る。編集の場合は旧設定・旧データのまま。回転では入力を保持し、取得を二重開始しない。初回追加のためだけの永続ジョブ・独自の復旧ウィザードは作らない。

登録済みソースは既存の未処理要求・操作記録を使い、アプリ起動時とWorker開始時に点検する。無効化後の古い要求を実行しない。共有辞書への結果が不明なら、同じ操作を繰り返す前に記録と現状を照合する。

通常の反映がキャンセル（Workerの停止・画面を閉じた・プロセス終了）で中断した場合、次のWorkerの処理で操作記録に基づいて自動的に再開する。画面から始めた反映が画面を閉じたことで中断した場合は、その場でWorkerを登録する（次回起動を待たない）。中断した反映がある間はほかのソースが待機するため、再開を先に行う。結果不明・外部変更などで「要確認」になった反映と、復旧の計画は自動では進めず、ユーザーの選択を待つ。

画面からの有効化・無効化・削除と、追加・編集の成功後の反映は、通信条件を持たない一意な反映チェーン（`ApplyWorker`、Android 12以上ではexpedited）が行う。画面は希望状態を保存するだけで、長い書き込みの間も操作できる。自分の未完了の計画があるソースの削除と、中断した反映の確認画面からの操作は、ユーザーの同意に基づくため画面から実行する。失敗した書き込みは自動では繰り返さない。

ユーザーが操作した取得（今すぐ同期・すべて同期）は、Android 12以上ではexpeditedのWorkとして登録し、割り当てがない場合は通常のWorkとして実行する。周期実行は通常のWorkのまま。

旧版へ完全に戻す自動補償、OEM固有の省電力設定操作（電池の最適化の除外を除く）、あらゆる停止点の網羅を新しい必須要件にしない。既存の手動復旧機能は保持し、通常操作から必要な場合だけ案内する。OSの強制停止中の実行や即時復旧は約束しない。
